# Cada herramienta en su función: SQL, motor local, Python y formatos

:::decision
Cada paso de un análisis tiene su herramienta. La consulta que recorre muchas filas va al almacén de datos; la exploración repetida de un extracto, a un motor que corre en tu computadora, y las reglas de negocio con montos exactos, a Python. Lo que se guarda para volver a leerlo después va en un formato que conserve el tipo de cada columna, y por eso se usa Parquet y no CSV.
:::

:::quick-check
Si ya tienes práctica con esto, responde estas dos preguntas. Si aciertas ambas, puedes ir directo a la comprobación del final.

1. ¿Hace falta instalar un servidor de base de datos para consultar con SQL un archivo en tu computadora?
   - **Respuesta:** no. Un motor embebido corre dentro del mismo programa que lo usa, sin servidor, y consulta el archivo directamente.
2. Guardas un extracto como CSV y lo vuelves a leer. ¿Conserva que el monto era un número con dos decimales?
   - **Respuesta:** no. CSV no guarda tipos, así que el monto vuelve como texto o con un tipo adivinado a partir de una muestra.
:::

## Doce semanas del Sur {#caso}

La analista quiere ver cómo se movió el pipeline del Sur durante las doce semanas del cuarto trimestre. Piensa explorarlo varias veces en los próximos días, cada vez con una pregunta distinta. Un agente le propone dos caminos: repetir la consulta al almacén de datos cada vez que ella pregunte algo, o descargar todo una vez como CSV y trabajar sobre ese archivo. Los dos funcionan, pero los dos tienen un costo que no se ve a primera vista. Para elegir bien hay que conocer dos piezas nuevas, un motor que corre en tu computadora y un formato de archivo que conserva los tipos.

## Un motor que corre en tu computadora {#embebido}

Hasta ahora, cada consulta SQL viajaba a un almacén, que la ejecutaba con sus propias máquinas. Existe otra posibilidad. Un **motor analítico embebido** es una base de datos que funciona dentro del mismo programa que la usa, por ejemplo dentro de un script de Python. El motor que revisamos para este manual no necesita que instales ni mantengas un servidor, no depende de otros programas y procesa los datos por columnas, es decir, trabaja con lotes de valores de una misma columna en vez de avanzar fila por fila. Eso lo hace adecuado para análisis que suman, agrupan o cruzan buena parte de los datos :cite[src-duckdb-why]. Puede trabajar en memoria, sin guardar nada al terminar, o sobre un archivo de base de datos que queda guardado en el disco :cite[src-duckdb-python].

Ese diseño tiene un límite. En modo embebido, un solo programa puede leer y escribir el archivo de base de datos; varios programas pueden abrirlo a la vez, pero solo para leer :cite[src-duckdb-concurrency]. Por eso sirve para el análisis local de una persona o de un agente, y no para que varias personas escriban al mismo tiempo en la misma base [inferencia].

Para el caso del Sur, lo más útil es que el mismo motor puede consultar un archivo Parquet sin importarlo antes: basta con escribir la ruta del archivo dentro de un `SELECT`. Además, lee solo las columnas que pide la consulta y aprovecha los filtros del `WHERE` para saltarse las partes del archivo que no los cumplen :cite[src-duckdb-parquet]. Una consulta que solo usa la región y el monto no tiene que recorrer el resto de las columnas.

## Parquet guarda los tipos; CSV, no {#formatos}

Ese archivo Parquet es la otra pieza. **Parquet** es un formato de archivo abierto, mantenido por la fundación Apache, que guarda los datos por columnas y los comprime :cite[src-parquet-overview]. Al final de cada archivo van sus metadatos, la información que describe los datos que contiene :cite[src-parquet-file-format]. Entre esos metadatos está el esquema, es decir, el nombre y el tipo de cada columna :cite[src-parquet-thrift]. Como el archivo se divide en bloques de filas, también se guardan los valores mínimo y máximo de cada bloque, y con ellos un lector puede saltarse los bloques que un filtro descarta :cite[src-parquet-readme]. Para los montos, Parquet tiene un tipo decimal en el que se declaran la precisión, que es la cantidad total de dígitos, y la escala, que es la cantidad de decimales :cite[src-parquet-logical-types].

**CSV**, en cambio, es texto con los valores separados por comas. Su descripción define registros, campos, comillas y un encabezado opcional, pero ningún tipo de dato :cite[src-ietf-rfc4180]. Todo lo que diga cuál columna es número y cuál es fecha tiene que reconstruirlo quien lo lee. El lector de CSV de Python, por ejemplo, devuelve todo como texto, salvo que se le indique otra cosa :cite[src-python-csv]. El motor embebido, por su parte, adivina los tipos a partir de una muestra de las primeras líneas, y su documentación advierte que un valor que aparece después de la muestra puede no encajar en el tipo adivinado; para evitarlo, se fijan los tipos de forma explícita :cite[src-duckdb-csv].

Nada de esto vuelve inútil a CSV. Sigue siendo una buena forma de entregar un archivo que alguien abrirá en una hoja de cálculo, siempre que la descripción de las columnas vaya aparte [inferencia].

## Python, para las reglas y los checks {#python}

Queda el tercer tipo de trabajo, el que aplica las reglas de negocio. En el caso de Altiplano vive en Python, en el script de reconciliación: ahí se aplican las políticas declaradas, como qué hacer con un duplicado, y ahí se calculan los montos con decimales exactos y no con la coma flotante, que no representa bien muchos números decimales :cite[src-python-floatingpoint]. También es Python el que corre el check y termina con un código de salida, un número que el programa devuelve al terminar para indicar si todo salió bien :cite[src-python-sys]. SQL puede expresar muchas de esas reglas, pero el check conviene escribirlo por un camino distinto al del cálculo, como verás en la lección 6 [inferencia].

## Qué herramienta para cada paso {#eleccion}

Con las tres piezas a la vista, la elección queda así [inferencia]:

| Paso | Herramienta | Por qué |
| --- | --- | --- |
| Filtrar y agregar la tabla histórica | SQL en el almacén | Los datos y el cómputo están allí; se trae solo el resultado |
| Explorar varias veces un extracto en tu computadora | Motor embebido sobre Parquet | Sin servidor, lee solo las columnas necesarias y conserva los tipos |
| Aplicar la política de duplicados, los alias y la conversión de moneda | Python | Reglas explícitas, decimales exactos y pruebas |
| Guardar un resultado intermedio que otro paso leerá | Parquet | Esquema y tipos dentro del archivo |
| Entregar un archivo para una hoja de cálculo | CSV con las columnas descritas aparte | Lo abre cualquiera |

:::worked-example{title="Las doce semanas, bien resueltas"}
**Una sola consulta al almacén.** Se filtra a las doce fechas del trimestre y a las columnas que usa el cálculo, y el resultado se guarda una vez como Parquet, con la consulta y la fecha de extracción al lado.

**Las exploraciones, en local.** La analista usa el motor embebido sobre ese archivo todas las veces que haga falta, sin volver a consultar el almacén.

**Las reglas y el contrato, en Python.** La deduplicación, la conversión de euros y el cálculo de los KPI quedan en el script.

**Por qué no repetir la consulta cada vez.** Gasta cómputo y, si la tabla cambió entre una consulta y otra, dos exploraciones verían datos distintos sin que nadie lo note.

**Por qué no CSV.** El monto y la fecha de cierre volverían como texto o con un tipo adivinado, y una fecha vacía, como la de OPP-1021, puede cambiar el tipo que el lector adivina para toda la columna.

**Y si el agente propone guardar el monto como número de coma flotante «para que pese menos».** Se le pide el tipo decimal con dos decimales, porque la coma flotante no representa con exactitud los montos decimales.
:::

::check-questions

:::summary
- Un motor embebido consulta archivos locales con SQL, sin servidor; en ese modo, un solo programa escribe.
- Parquet guarda el esquema, los tipos y los valores mínimo y máximo de cada bloque, que permiten saltarse lo que no hace falta; tiene un tipo decimal para montos.
- CSV no guarda tipos: los datos vuelven como texto o con tipos adivinados a partir de una muestra.
- Python aplica las reglas de negocio con decimales exactos y corre los checks.
- Se consulta una vez en el almacén, se guarda el extracto en Parquet y se explora en local.
:::
